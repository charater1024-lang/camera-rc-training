# 주간과 야간 자율주행 인식 모델 검토

> **과거 실험·연구/인터페이스 참고 문서.** 아래 수치와 진행 표현은 문서 작성 당시의 범위입니다. 현재 완료 결과와 취소/미검증 항목은 [RESULTS](RESULTS.md), 재현 절차는 [REPRODUCIBILITY](REPRODUCIBILITY.md), 운용 한계는 [LIMITATIONS](LIMITATIONS.md)를 우선 확인하십시오. 예제 명령은 설치 시 실행되지 않으며 학습·다운로드·서비스·제어의 새 실행을 뜻하지 않습니다. 로컬 경로는 이 공개본에서 프로젝트 상대 예제로 바꿨습니다.

2026년 10월 22일 검토. 대상은 RTX 3080 Laptop 16GB에서 학습하고 VRAM 4GB 또는 8GB와 RAM 16GB에서 실행할 카메라 인식 시스템이다.

현재 권장은 **주야간 공통 모델을 기본으로 유지하고, 야간 장애물의 실제 라벨과 조건별 평가를 보강한 뒤 필요하면 경량 모델로 증류하는 것**이다. 주간 모델과 야간 모델 두 개가 필수인 것은 아니다. 이는 문헌과 현재 데이터에 근거한 설계 판단이며, 우리 모델에서 어느 방식이 더 좋은지는 별도 비교가 필요하다. 진행 중인 3epoch 학습과 고정 평가 조건은 유지한다.

| 방식 | 기대 효과 | 실행 비용과 확인할 문제 | 현재 우선순위 |
|---|---|---|---|
| 주야간 공통 모델 | 공통 도로·객체 특징을 함께 학습 | 야간 표본이 묻히거나 주야간 성능이 상충하는지 확인 | 가장 먼저 개선 |
| 공유 백본과 작은 조건별 헤드 또는 어댑터 | 대부분의 연산을 공유하면서 조명별 차이를 반영 | 조건 추정 오류, 혼합 조명, 실제 추가 지연을 평가 | 공통 모델의 한계가 확인되면 비교 |
| 별도 주간 모델과 야간 모델 중 하나 선택 | 조건별로 다른 표현을 학습 | 상주 메모리 또는 교체 지연, 박명·터널 전환, 잘못된 선택 | 현재 자료로는 채택 근거 부족 |
| 두 모델 동시 추론 후 결합 | 서로 다른 예측을 활용 | 두 번의 추론과 결합 비용, 같은 원인으로 틀리는 경우 | 우선 운용안으로 부적합 |
| 큰 교사에서 작은 공통 학생으로 증류 | 학습 때 큰 모델을 활용하고 실행 비용을 줄임 | 교사의 오류 전파와 작은 물체·야간 성능 손실 | 속도 부족 시 우선 후보 |

두 별도 모델 중 하나만 실행한다면 연산량이 항상 두 배가 되는 것은 아니다. 두 모델을 상주시킬 때의 가중치·버퍼와 교체 방식의 지연을 각각 측정해야 한다. 같은 모델을 여러 카메라에 공유하면 가중치는 공유할 수 있지만 영상 처리량은 그대로 필요하다. 시계나 전체 영상의 평균 밝기 하나로 주야간을 선택하면, 낮의 터널이나 밤의 밝은 간판, 전방과 후방의 서로 다른 노출을 제대로 표현하기 어렵다. 조건별 분기는 카메라별 노출·화질 정보와 영상 특징을 함께 사용하고 전환 중 예측 변화를 시험하는 설계가 필요하다.

문헌에서는 조건별 전용 모델의 우위가 일관되지 않았다. ACDC의 동일 계열 모델 비교에서 야간 19클래스 mIoU는 HRNet 전용 63.2→통합 65.3, DeepLabv3+ 59.2→60.9였다. 반대로 DeepLabv2는 45.4→45.3으로 조금 낮았다. 통합 모델은 안개·야간·비·눈을 함께 학습했다. 학습 데이터량과 반복 횟수가 완전히 동일한 실험은 아니며, 이 수치는 우리 도로 2클래스 IoU나 충돌 확률을 뜻하지 않는다. [ACDC 원 논문 표 6 및 학습 설정](https://arxiv.org/html/2104.13395v3)

Refign은 대응되는 정상 조건 영상을 학습 중 정렬하여 악조건 학습을 돕는다. 공식 구현은 이 추가 과정이 추론 비용을 늘리지 않는다고 설명한다. 대응 영상과 정렬 신뢰도가 필요하므로 서로 다른 시점의 차량·보행자를 그대로 정답으로 옮겨서는 안 된다. 현재 자기 점검 정책은 예측을 정답으로 사용하는 학습을 허용하지 않으므로, 원 논문의 비지도 의사 라벨 방식은 즉시 실행할 후보가 아니다. [Refign 공식 구현](https://github.com/brdav/refign)

NightAdapter는 주파수 특성을 이용해 다양한 야간 환경에 적응하는 2025년 연구다. 작은 추가 모듈이라는 설명이 전체 추론 모델까지 작다는 뜻은 아니다. 논문의 ViT-L/DINOv2와 Mask2Former 구성은 현재 YOLO 모델에 바로 꽂을 수 있는 모듈이 아니며, 공유 어댑터 설계의 연구 참고로 둔다. [NightAdapter 논문](https://openaccess.thecvf.com/content/CVPR2025/papers/Bi_NightAdapter_Learning_a_Frequency_Adapter_for_Generalizable_Night-time_Scene_Segmentation_CVPR_2025_paper.pdf)

밝기 보정은 반드시 인식 성능으로 평가해야 한다. FeatEnHancer의 ACDC 실험에서 기본 모델 mIoU 45.7에 비해 RetinexNet 전처리는 41.9, ZeroDCE는 43.4였고, 인식 특징을 직접 개선한 방법은 54.9였다. 이것이 모든 보정에 적용되는 결론은 아니지만, 화면이 밝고 보기 좋아졌다는 이유로 보정을 채택할 수 없음을 보여 준다. 원본과 보정 입력의 오인율·재현율·지연을 함께 비교한다. [FeatEnHancer 표 4](https://openaccess.thecvf.com/content/ICCV2023/papers/Hashmi_FeatEnHancer_Enhancing_Hierarchical_Features_for_Object_Detection_and_Beyond_Under_ICCV_2023_paper.pdf)

현재 데이터에서 먼저 해결할 문제는 야간 장애물의 라벨 부족이다.

| AI Hub 자료 | 학습 이미지 | 검증 이미지 | 촬영 조건 |
|---|---:|---:|---|
| 13번 | 6,278 | 783 | 주간 도심 |
| 14번 | 6,351 | 799 | 주간 자동차 전용도로 |
| 15번 | 6,303 | 785 | 야간 자동차 전용도로 |

야간 학습에서 보행자·자전거·오토바이·라이더·콘이 주석된 프레임은 각각 **2·2·3·2·8장**이고, 야간 검증에서는 모두 0장이다. 반면 차량 주석은 학습 5,829장, 검증 717장에 있다. 주석이 없다는 것은 장면에 객체가 없다는 뜻이 아니다. 야간 픽셀 중 약 80%는 ignore255이며 trafficDrum과 warningTriangle도 현재 무시된다. 따라서 야간 도로 지표가 높아져도 야간 보행자나 작은 낙하물을 잘 피한다고 판단할 수 없다. [공개 데이터 감사 요약](DATASETS.md)

전체 학습 37,864장에는 기존 BDD 10,000장과 VKITTI 8,932장이 포함된다. 현재 통합 목록에서 이 두 출처의 시간대가 일관되게 정리되어 있지 않으므로, AI Hub 야간 6,303장을 전체 야간 이미지 수로 표현하지 않는다. 주간 도심과 야간 전용도로의 차이는 밝기뿐 아니라 도로 종류도 포함한다. 14번과 15번도 같은 경로의 낮밤 대응 영상은 아니다.

현행 YOLO26x-sem은 단일 RGB 프레임에서 도로/비도로만 분류한다. 기본 HSV 밝기·색상 증강과 비도로 손실 가중치 2가 이미 적용돼 있다. 추가 후보는 같은 설정을 중복 추가하는 대신, 학습 자료의 명시적 장애물 표본 구성이나 실제 센서에 근거한 저조도 노이즈·노출 변화·눈부심 중 하나를 검증해야 한다. 무시 영역을 비도로 정답으로 바꾸지 않는다.

도로 분할만으로 모든 장애물을 탐지하는 시스템이 완성되지는 않는다. 현재 평가기의 비도로 픽셀 오인율과 공개 장애물 마스크 오인율은 객체별 탐지 재현율과 다르다. 작은 장애물 인스턴스 검출 평가는 아직 지원되지 않는다. 향후에는 객체 검출·추적, 도로 분할, 거리와 가림 판단을 연결하고 각 기능의 정답으로 검증해야 한다. 모델의 낮은 확신이나 영상 품질 저하를 계획 단계에 전달하는 기능도 별도로 시험한다. 시간축 처리를 추가할 때는 흔들림 감소뿐 아니라 새 장애물을 이전 프레임으로 덮어버리는 지연을 확인한다.

추가 데이터의 우선순위는 양보다 빠진 조건과 라벨이다.

| 자료 | 목적 | 사용 범위와 주의점 |
|---|---|---|
| ACDC 야간 | 야간 도로·객체 픽셀 분할 | 야간 학습 400장, 검증 106장, 테스트 500장. 테스트 정답은 비공개. 공식 분할 유지 |
| NightOwls | 야간 보행자와 라이더 검출 | 약 279k프레임, 40시퀀스. 검출·추적 라벨을 도로 마스크 정답으로 취급하지 않음 |
| BDD 시간대 메타데이터 | 보유 자료의 주간·야간·박명 구성 확인 | 영상 ID와 원본 라벨 태스크를 맞춰 연결. 검출 상자를 픽셀 분할 정답으로 바꾸지 않음 |
| 실제 장착 카메라 녹화 | 국내 야간·전조등·검은 물체·콘·젖은 노면·터널 전환 | 동기화·노출·차속·거리 정답을 기록하고 클립별로 분리 |

ACDC의 공개 학습·검증 분할과 비공개 테스트 구성은 [공식 대회 지침](https://ethz.ch/content/dam/ethz/special-interest/itet/cvl/icu-dam/images/ACDC_Challenge_2022-guidelines.pdf)에 따른다. NightOwls의 PNG 학습 영상은 공식 표기 135GB, 검증 50GB로 크므로 무작정 모두 추가하기보다 부족한 조건을 먼저 확인한다. 비상업적 연구·개인 실험 조건이 명시되어 있다. [NightOwls 설명](https://www.nightowls-dataset.org/about/), [다운로드와 이용 조건](https://www.nightowls-dataset.org/download/)

실행 성능을 높일 때는 큰 모델을 두 개로 나누기보다, 큰 교사의 정보를 작은 공통 모델에 전달하는 증류를 우선 비교할 가치가 있다. 이때 사람의 정답 라벨을 기본 감독으로 유지하고 교사의 출력은 보조 신호로 구분한다. 교사가 틀린 장애물 판단을 정답으로 확정하지 않는다. 분할 증류 연구는 Cityscapes 학생 모델 mIoU 70.2→72.7 사례를 보고했으나, 우리 데이터의 개선량은 새 실험으로 측정해야 한다. [Knowledge Adaptation 원 논문](https://openaccess.thecvf.com/content_CVPR_2019/html/He_Knowledge_Adaptation_for_Efficient_Semantic_Segmentation_CVPR_2019_paper.html)

학생 후보로는 현재 학습기와의 호환성을 먼저 검토할 작은 semantic 모델과, 별도 어댑터가 필요한 PIDNet-S를 고려한다. PIDNet-S 논문의 Cityscapes 78.6 mIoU·93.2FPS는 RTX3090·2048×1024 조건으로, MSI 4GB 노트북의 예상 성능으로 쓰지 않는다. FP16/INT8 변환도 야간·작은 장애물 정확도를 다시 측정해야 한다. [PIDNet 표 6](https://openaccess.thecvf.com/content/CVPR2023/papers/Xu_PIDNet_A_Real-Time_Semantic_Segmentation_Network_Inspired_by_PID_Controllers_CVPR_2023_paper.pdf)

다음 비교는 기존 자기 점검 예산 안에서 한 번에 하나씩 진행한다.

1. 진행 중인 3epoch 학습과 같은 조건의 기존 모델 비교를 완료한다. AI Hub 13/14/15별 도로 IoU·재현율·비도로 오인율을 보고하되 지원되지 않는 야간 객체 지표는 N/A로 둔다.
2. 학습 데이터에서 시간대와 객체 라벨의 지원 범위를 정리하고, 확인 가능한 촬영 그룹·클립을 분리한 개발셋을 고정한다. 경로·촬영일 정보가 확보되면 함께 묶는다. 과거 모델이 본 자료일 수 있으므로 독립 시험이라고 부르지 않는다. 새 후보의 체크포인트 선택용 val에는 이 개발셋을 연결하고, 공식 검증과 공개 장애물 40장은 보고 전용으로 유지한다.
3. 학습/개발 자료에서 확인한 원인 하나에 대해 표본 구성 또는 센서 기반 증강 중 변경 하나를 사전 기록한다. 현재 예산은 새 후보 1개·최대 3epoch이며, 이 문서의 여러 아이디어를 한꺼번에 실행하는 것이 아니다. 근거가 없으면 학습 반복 대신 필요한 데이터를 명시한다.
4. 개발셋에서는 주야간 평균뿐 아니라 가장 나쁜 조건과 도로 재현율 손실을 본다. 같은 영상에 대한 차이를 클립 단위로 집계하고 충분한 클립 수가 있을 때 부트스트랩 구간을 계산한다. 프레임을 모두 독립 표본으로 간주하지 않는다. 허용 손실과 선택 규칙은 후보의 공식 평가 전에 정한다.
5. 별도 모델 또는 조건별 모듈의 구조 비교는 후속 연구로 남긴다. 공통 초기화·같은 라벨·동등한 총 학습 예산·같은 입력 크기로 비교하고, 조건을 정답으로 골라주는 이상적 전환과 실제 조건 추정 전환을 분리한다. 박명·터널·노출 급변의 전환 지연과 예측 흔들림까지 측정해야 분기의 이득을 판단할 수 있다.
6. 속도는 실제 동일 GPU에서 영상 1개/8개, 순차/배치, 같은 정밀도·해상도·입력으로 전체 처리 지연 p50/p95/p99와 메모리를 비교한다. 모델 교체·전처리·후처리 비용도 포함한다. 최종 탑재 하드웨어에서는 카메라 수신·노출·동기화 지연까지 추가 측정한다.

맑은 낮, 박명, 밝은 야간, 어두운 야간, 눈부심, 젖은 노면, 터널 전환을 각각 기록하되 실제 자료가 없는 칸은 비워 둔다. 이 조합의 검증 없이 주야간 평균 수치로 80km/h 운행이나 무사고를 주장하지 않는다. 80km/h에서는 100ms 동안 약 2.22m 이동한다는 계산은 지연의 의미를 보여 줄 뿐이며, 장애물 인지 거리나 제동 성능을 검증한 결과는 아니다.
