## 진행 상태를 읽는 법

이번 작업은 실제 공개 자료 다운로드와 일회성 학습 대기열을 시작했다. 아래의 용량·이미지 수는 원본 목록과 예정 분할이며, 다운로드·학습 완료를 뜻하지 않는다.

- 현재 실행 단계: `runs/large_data_queue_v1/status.json`
- 단계별 준비·학습·평가 로그: 같은 폴더의 `*.log`
- Virtual KITTI 2 완료: `datasets/virtual_kitti2/{semantic,metadata,rgb}_complete.json`
- ACDC 완료: `datasets/acdc/DOWNLOAD_COMPLETE.json`
- A2D2 완료: `datasets/a2d2_semantic_v1/DOWNLOAD_COMPLETE.json`
- 실제 학습 완료: 해당 `runs/<stage>/summary.json`의 `training_complete=true` 및 `diagnostic=false`
- 성능 비교: `runs/<stage>/evaluation/comparison.json`

전원·인터넷이 유지되어야 전송이 진행된다. ACDC는 서버가 Range 요청을 지원하지 않아 중단 후 전체 파일을 다시 받아야 한다. 실패한 부분 파일은 보존한다. 다른 두 다운로드는 검증된 부분/파일을 재사용한다. 일회성 대기열은 최대 72시간이며 예약·반복 실행 서비스가 아니다. `runs/large_data_queue_v1/STOP_REQUESTED` 파일을 만들면 준비/학습 대기열과 그 자식 작업이 중단된다. 별도로 이미 실행된 다운로드 프로세스는 이 파일로 중단되지 않는다. 실패 결과는 덮어쓰지 않으므로 재실행 전 `status.json`과 로그를 확인해야 한다.

## 확보 대상과 학습 분할

| 자료 | 다운로드 대상 | 전송 용량 | 새 학습용 | 검증 | 보류 시험 |
|---|---|---:|---:|---:|---:|
| Virtual KITTI 2.0.3 | RGB·의미 라벨·카메라 메타데이터 | 8,572,884,998바이트 | 28,920 | 8,940 | 4,660 |
| A2D2 | 6방향 RGB·의미 라벨 41,277쌍 | 152,021,120,762바이트 + 작은 메타데이터 | 33,330 | 4,873 | 3,074 |
| ACDC | adverse/reference RGB 8,012장, adverse train/val 라벨 | RGB 공시 약 15.6GB + GT 133,426,176바이트 | 1,600 | 406 | adverse 2,000장, 공개 정답 없음 |

약 176GB의 추가 전송이다. 압축본과 추출본을 함께 보존하고 A2D2 학습용 축소본도 만들기 때문에 디스크 사용량은 전송량보다 크다. 시작 시 D: 여유 공간은 약 1.73TB였다. A2D2의 동일 파일 중복이 발견되면 분할 내 중복은 제외하므로 실제 학습 수가 표보다 줄 수 있다. 분할 간 동일 파일은 오류로 처리한다.

기존 BDD 70,000장을 포함한 최종 학습용 합계는 중복 제외 전 **133,850장**이다. 보류 시험 자료와 공개 정답이 없는 영상을 억지로 학습 정답으로 만들지 않는다. Virtual KITTI의 42,520장은 독립 도로 42,520개가 아니라 **원본 5개 장면의 날씨·시점·스테레오 변형**이다.

공식 배포와 조건:

- [Virtual KITTI 2](https://europe.naverlabs.com/proxy-virtual-worlds-vkitti-2/): 무가입, CC BY-NC-SA 3.0. 공식 MD5와 로컬 SHA256 검증.
- [A2D2 공식 AWS 배포](https://registry.opendata.aws/aev-a2d2/): 무가입, CC BY-ND 4.0. 개별 파일의 고정 크기·single-part MD5 ETag·로컬 SHA256 검증. LiDAR 파일은 이번 영상 학습 입력에 필요하지 않아 전송 대상에 포함하지 않는다. 원본과 파생 마스크는 로컬 연구용으로 보존한다.
- [ACDC](https://acdc.vision.ee.ethz.ch/overview), [조건](https://acdc.vision.ee.ethz.ch/license): 현재 공식 공개 다운로드 API로 무가입 취득 가능. 비상업 연구 조건과 원본 배포 제한을 보존한다. 임시 다운로드 토큰은 로그·보고서에 남기지 않는다.
- LostAndFound의 확인된 기관 저장소는 이용 동의가 필요한 gated 자료였다. 이번 무가입 다운로드에는 포함하지 않았다.

## 이번에 연결한 학습

1. `large_vkitti_stage1_v1`: BDD 전체 70,000 + Virtual KITTI train 28,920 = 98,920장을 1epoch 학습한다.
2. `large_all_stage2_v1`: 위 자료에 A2D2·ACDC train을 추가하여 최대 133,850장을 1epoch 학습한다.
3. 각 실험은 원래의 BDD 전용 기준 체크포인트에서 독립적으로 시작한다. 이전 CamVid/KITTI 추가학습 모델은 초기값으로 사용하지 않는다.
4. 각 단계마다 같은 설정과 검증 자료로 원래 BDD 모델과 후보를 모두 평가한다. 새 자료의 검증과 기존 BDD/CamVid/KITTI 검증을 각각 보고한다.
5. RoadObstacle21 공개 GT 30장, RoadAnomaly21 공개 GT 10장으로 장애물을 도로로 부르는 비율을 추가 비교한다. 이 자료는 이미 이전 실험의 문제점을 확인하는 데 사용했으므로 개발용 회귀 평가 자료이며, 새로 봉인한 최종 시험 자료가 아니다.

설정은 TinyUNet width16, 입력 높이192×너비320, batch16, CUDA AMP, workers2, 학습률0.0002다. epoch마다 학습 manifest 전체를 중복 추출 없이 한 번씩 사용한다. 학습 손실의 도로/비도로 클래스 가중치를 `[1,2]`로 두어 비도로 오차의 상대 기여를 높인다. 검증 손실과 픽셀 지표는 가중하지 않는다. 가중치 변경은 충돌 위험 확률을 추정하거나 보정하는 방법이 아니다.

이번 비교는 데이터·추가 학습·손실 가중치가 함께 바뀌는 실험이다. 점수가 달라져도 변화 전부를 데이터 양의 효과로 단정할 수 없다. 한 epoch는 대용량 첫 비교 실험이지 수렴 완료를 의미하지 않는다.

누출 방지의 구체적인 예:

- Virtual KITTI Scene01은 기존 KITTI 검증 자료와 같은 원본 주행 `2011_09_26_drive_0009`에서 유래하므로 검증에 유지한다. Scene02는 보류 시험, Scene06/18/20은 학습이다. 같은 장면의 모든 날씨·양쪽 카메라가 같은 분할에 들어간다.
- A2D2는 20181008 날짜를 검증, 20181107 날짜를 보류 시험으로 묶는다. 보류 시험 날짜에는 전방 중앙 라벨만 있다는 한계가 있다.
- ACDC는 공식 지리적 train/val 분할을 유지한다. 동일 recording 이름이 양쪽에 있어도 임의 프레임 분할을 새로 만들지 않는다. 불확실성 invIds는 장애물 정답이 아니며, 공식 최종 semantic GT가 유효한 영역은 그대로 사용한다.

현재 실험은 **road_surface_v1 도로/비도로 분할 학습**이다. 3D 객체 검출, 거리·속도 추정, 동기 다중 카메라 융합, 경로 계획의 안전성까지 함께 학습·검증한 것으로 해석하면 안 된다. A2D2의 여러 방향 라벨 영상도 모든 시점에 동기화된 6개 묶음이 아니다. 원본·캘리브레이션 메타데이터는 향후 모델을 위해 보존한다.

현재 입력 해상도에서는 원본의 아주 작은 장애물 영역이 1~수 픽셀로 줄 수 있다. 데이터 양과 손실 가중치만으로 사라진 영상 정보를 복원할 수 없다. 후속 실험에서는 높은 해상도 또는 관심 영역 crop, 객체 검출, 시간축 추적, 실제 장착 카메라의 자료가 필요하다. 원본은 이 목적을 위해 보존했다.

## 테슬라 카메라 수와 관측 역할

아래는 **현재 미국 Model Y 공식 매뉴얼**의 구성이며 모든 연식·차종을 뜻하지 않는다. 역할은 장착 위치와 공개 기능을 바탕으로 설명한 관측 목적이고, 테슬라 내부 모델이 카메라별로 일을 독점 분담한다는 의미는 아니다.

| 위치 | 개수 | 관측 목적 |
|---|---:|---|
| 앞유리 위 | 2 | 전방 도로·차선·차량·신호 등 |
| 좌우 도어 필러 | 2 | 측면과 교차 방향 |
| 좌우 앞 펜더 | 2 | 측후방·사각지대·차선 변경 주변 |
| 뒤 번호판 위 | 1 | 후방·후진 주변 |
| 앞 범퍼 | 1 | 차량 가까운 전방 |
| 실내 | 1 | 운전자 주의 상태 감시, 도로 장애물 관측용 아님 |
| 합계 | **외부8 + 실내1 = 9** | 도로 주변 인식 관점에서는 외부8대 |

[Model Y 공식 카메라 매뉴얼](https://www.tesla.com/ownersmanual/modely/en_us/GUID-682FF4A7-D083-4C95-925A-5EE3752F4865.html). [Model 3 공식 매뉴얼](https://www.tesla.com/ownersmanual/model3/en_us/GUID-682FF4A7-D083-4C95-925A-5EE3752F4865.html)은 앞 범퍼 카메라를 장착 차량에 한한다고 설명하므로 현재 문서상 외부7~8대 + 실내1대로 구분해야 한다. 구형 Model 3은 앞유리 구성이 다르다.

카메라를 테슬라와 같은 개수로 설치하는 것만으로 비슷한 성능을 얻을 수는 없다. [테슬라의 공개 기술 설명](https://www.tesla.com/AI)은 카메라별 영상 인식뿐 아니라 여러 카메라의 비디오를 이용한 상공 시점/3D 표현, 시간·공간을 결합한 정답, 경로 계획, 대규모 평가를 함께 설명한다. [FSD Supervised 공식 안내](https://www.tesla.com/support/fsd)도 운전자의 적극적인 감독을 요구하며 완전 자율 차량으로 바뀌는 것은 아니라고 명시한다.

이 프로젝트에서 맞춰야 할 것은 먼저 시야·시각·기하·지연이다.

- 실제 장착 높이·방향·화각과 렌즈 왜곡을 측정하고, 전후좌우와 차량 바로 앞의 사각지대를 확인한다.
- 노출 시각 기준으로 카메라를 동기화한다. 호스트 수신 시각만 같다고 촬영 시각까지 같은 것은 아니다.
- 카메라 사이의 위치·각도를 보정하고, IMU·차속·조향 상태의 시각도 연결한다.
- 같은 객체를 여러 카메라·연속 프레임에서 연결하여 거리·상대 속도를 추정한다. 관계없는 공개 이미지를 가짜 동기 묶음으로 만들지 않는다.
- MSI GTX1650급 4GB 환경에서 디코딩·전처리·추론·융합·계획·제어 전체 지연과 메모리를 실제 측정한다. 카메라 8대 실시간 처리 성능은 아직 이 장치에서 확인하지 않았다.

현재 프로파일의 `dry_run`, `models_validated_for_control=false`, `capture_timing_validated=false`는 유지한다. 어느 후보도 자동 배포하지 않는다. 도로 IoU 상승이나 회귀 지표 개선은 무사고 보장이 아니며, 실제 차량의 제동·감시·고장 대응 검증을 대체하지 않는다.
